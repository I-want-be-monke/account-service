# UI-01. Проверка в Chrome, Edge, Firefox и Яндекс Браузере

`scripts\ui-test.cmd` запускает headless Selenium WebDriver. `--browser all` последовательно проверяет Chrome, Edge и Firefox. Для Яндекс Браузера предусмотрен отдельный запуск с официальным Яндекс Драйвером. Нужны Node.js 20 или новее, Docker Desktop, запущенный изолированный стенд E11 и настоящие исполняемые файлы браузеров. Установку браузеров через Selenium Manager сценарий запрещает. Укажите совместимые драйверы явно, чтобы запуск использовал локальные файлы.

Сценарий проверяет Docker Compose-проект `account-service-e11`, имя БД `account_service_e11`, сеть и том проекта, порты `127.0.0.1:18448` и `127.0.0.1:55438`, а затем проверяет готовность `https://localhost:18448` по HTTPS. Он использует тестовые пароли ролей из `.local\e11\stand.env` и существующего пользователя `e11-client-001`. Параметр `--client` позволяет выбрать другого пользователя из набора `e11-client-NNN`. Каждый браузер создаёт отдельного синтетического клиента, счёт и проводки. Они сохраняются в тестовой БД для сверки с протоколом.

## Запуск из CMD

Запустите изолированный стенд и подготовьте его сертификат для браузеров. На чистом стенде выполните однократную [генерацию профиля `smoke`](../performance/README.md). Если синтетический набор уже есть, используйте его.

```cmd
tests\performance\stand.cmd start
tests\ui\prepare-stand.cmd
```

Для команды подготовки нужен OpenSSL 1.1.1 или новее, например из Git for Windows. Она поднимает только приложение в `account-service-e11` и сохраняет тестовые TLS-файлы в `.local\e11-continuation\ui-tls`. Для Firefox распакуйте отдельную копию официального дистрибутива и создайте `distribution\policies.json` рядом с `firefox.exe`. Укажите абсолютный путь к тестовому CA с экранированными обратными косыми чертами. [Политика Certificates в Firefox](https://firefox-admin-docs.mozilla.org/reference/policies/certificates/)

```json
{
  "policies": {
    "Certificates": {
      "Install": ["C:\\vyz\\incheneria\\account-service\\.local\\e11-continuation\\ui-tls\\ca.pem"]
    }
  }
}
```

Установите зафиксированные зависимости из каталога `tests\ui`.

```cmd
cd /d C:\vyz\incheneria\account-service\tests\ui
npm.cmd ci --ignore-scripts
cd /d C:\vyz\incheneria\account-service
```

Укажите пути для подготовленных браузеров, драйверов и TLS-файлов. Для каждого запуска используйте новый каталог под `.local`. Пример ниже использует пути повторной проверки редизайна 23.11.2026. Для неё сохранены прежние сертификаты, создан новый каталог TLS, а Firefox скопирован в отдельную тестовую установку с политикой доверия к новому CA. Локальная копия подготовки стенда находится в `.local\redesign-2026-11-23\prepare-ui.ps1`. При подготовке чистого стенда используйте пути CA и SPKI, которые вывел `prepare-stand.cmd`, и совместимый с установленной версией браузера драйвер.

```cmd
scripts\ui-test.cmd --browser all ^
  --chrome ".local\e11-continuation\browsers\chrome\chrome-win64\chrome.exe" ^
  --chrome-driver ".local\e11-continuation\browsers\chromedriver\chromedriver-win64\chromedriver.exe" ^
  --edge "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" ^
  --edge-driver ".local\redesign-2026-11-23\browsers\edge-158.0.4370.33\msedgedriver.exe" ^
  --firefox ".local\redesign-2026-11-23\browsers\firefox\core\firefox.exe" ^
  --firefox-driver ".local\e11-continuation\browsers\geckodriver\geckodriver.exe" ^
  --ca ".local\redesign-2026-11-23\ui-tls\ca.pem" ^
  --spki ".local\redesign-2026-11-23\ui-tls\spki.txt" ^
  --output ".local\e11-continuation\ui-repeat-01"
```

Для дополнительного прогона используйте Node.js 22.4 или новее, установленный Яндекс Браузер и официальный драйвер соответствующей версии. [Релизы Яндекс Драйвера](https://github.com/yandex/YandexDriver/releases)

```cmd
scripts\ui-test.cmd --browser yandex ^
  --yandex "%LOCALAPPDATA%\Yandex\YandexBrowser\Application\browser.exe" ^
  --yandex-driver ".local\e11-continuation\browsers\yandex-driver\yandexdriver.exe" ^
  --ca ".local\redesign-2026-11-23\ui-tls\ca.pem" ^
  --spki ".local\redesign-2026-11-23\ui-tls\spki.txt" ^
  --output ".local\e11-continuation\ui-yandex-repeat-01"
```

Параметр `--ca` задаёт доверенный сертификат для предварительной проверки Node.js. Браузерам требуется доверие к тому же тестовому сертификату. Для изолированного Firefox подходит импорт тестового CA политикой частной установки. В Chrome и Edge `--spki` ограничивает исключение одним ключом тестового сервера и временными профилями прогона. До запуска браузеров Node.js проверяет цепочку, имя `localhost` и совпадение хеша SPKI с фактическим ключом. В WebDriver задано `acceptInsecureCerts=false`.

Яндекс Драйвер подключается к отдельному процессу Яндекс Браузера с чистым профилем и пустой стартовой вкладкой. При `ERR_CERT_AUTHORITY_INVALID` сценарий повторно проверяет сертификат и пробует штатное исключение сайта. Если в headless-режиме предупреждение остаётся, сценарий обрабатывает запросы сертификата в этой вкладке через DevTools. Продолжение разрешено только для `https://localhost:18448` после повторной проверки цепочки, имени и SPKI. Причина и число проверенных событий записываются в протокол. Настройки доверия Windows и основной профиль браузера остаются за пределами сценария. [Исключение для тестового сайта в справке Яндекса](https://browser.yandex.ru/help/ru/security/untrusted-sertificates)

## Покрытие и результаты

- Вход во все пять ролей с переходами по Tab и подтверждением по Enter. Для каждой роли проверяются доступные пункты sidebar и активный раздел, сворачивание desktop-меню и мобильное открытие с клавиатуры. Escape закрывает мобильное меню и возвращает фокус на его кнопку. Снимки dashboard сохраняются для всех пяти ролей.
- Оператор создаёт клиента и счёт, бухгалтер проводит начисление и оплату, затем корректирует обе суммы. История, выписка и отчёты сверяются с остатком 550,00 ₽. Проверяются отображение денег в формате `550,00 ₽` и точное значение в `data-value`. Руководителю запрещено проводить операции. Клиент видит собственный счёт и получает отказ при обращении к чужому.
- Выписка и четыре вида отчётов проверяются через формы. Клиент выбирается по отображаемому имени из поиска с помощью Arrow Down и Enter. Сценарий сверяет выбранный скрытый `clientId`, параметр запроса и результат отчёта. После сброса фильтра запрос включает всех разрешённых клиентов. Полные итоги движения сравниваются при размере страницы 1 и 2.
- Сценарий проверяет ошибки формы суммы и периода, пустой результат отчёта и фактически скачанные CSV с UTF‑8 BOM, разделителем `;` и ожидаемыми строками. Ссылки CSV и печати должны сохранять выбранного клиента и даты. Строки скачанного CSV сверяются с этим клиентом, денежные значения CSV сохраняют исходный контракт.
- Скрипт проверяет правило CSS для печати и вызов `window.print()` кнопкой. WebDriver отдельно формирует PDF печатной страницы выписки и отчёта. Визуально проверьте все страницы PDF. Интерактивное окно выбора принтера находится за пределами сценария.
- Dashboard пяти ролей, выписка и отчёт проверяются при CSS viewport 1920×1080, 1440×900, 1366×768, 768×1024 и 390×844. Chromium использует DevTools, Firefox использует WebDriver BiDi. После изменения размера сценарий проверяет реальные `innerWidth` и `innerHeight`, поскольку обычное окно headless-браузера может ограничивать минимальную ширину.
- Выписка и отчёт дополнительно проверяются при настоящем масштабе браузера 200%. В Chrome и Edge сценарий изменяет масштаб временного профиля, в Firefox — масштаб вкладки. Для Яндекс Браузера создаётся дополнительный временный профиль с масштабом 200% и копией текущей тестовой cookie. Сценарий сверяет удвоение `devicePixelRatio` и уменьшение CSS viewport вдвое. Для управления масштабом Firefox локальный geckodriver запускается с `--allow-system-access`. После проверки временные профили закрываются, основная сессия продолжает работу при масштабе 100%.
- Проверяются горизонтальный выход страницы и элементов, пересечения элементов управления, выход текста за пределы ячеек и ширина ключевых столбцов. На экране 390×844 сценарий проверяет переход Tab к таблице, видимую рамку фокуса и горизонтальную прокрутку стрелкой.

`summary.json` содержит общий итог, а `result.json` в каталоге каждого браузера содержит фактические версии, время, результаты 20 шагов, размеры, проверенные состояния навигации, UUID созданных данных и причины ошибок. Для Яндекс Браузера дополнительно записываются версия продукта из Windows, путь запущенного файла, User-Agent и версия драйвера. Снимки `home-<role>-<width>x<height>.png`, `statement-<width>x<height>.png`, `report-<width>x<height>.png` и `*-200-percent.png` предназначены для отдельной визуальной оценки. Скачанные файлы сохраняются в `downloads`, печатные документы в `statement-print.pdf` и `report-print.pdf`. Код выхода `0` означает успешное прохождение, `1` означает ошибку подготовки стенда или аргументов, `2` означает сбой одного или нескольких сценариев.

Для повторной проверки только печатных документов укажите `--print-only <каталог успешного предыдущего прогона>` вместе с прежними параметрами браузеров и новым `--output`. Сценарий берёт UUID и период из `result.json` соответствующего браузера, входит бухгалтером и формирует два PDF. В этом режиме выполняются четыре шага подготовки и печати. Проверка использует существующие финансовые данные. В `printArtifacts` записываются SHA-256 фактически выданного `/css/print.css`, SHA-256 и размер каждого PDF. Для Яндекс Браузера укажите каталог его отдельного предыдущего прогона.

## Окончательный прогон редизайна 23.11.2026

По уточнению пользователя итоговая приёмка выполнена только в Яндекс Браузере: 20/20 сценариев, пять ролей, пять размеров и реальный масштаб 200%. [Версии и результаты](../../docs/evidence/ui-redesign-2026-11-23/yandex/result.json). Для текущего ПК сохранены отдельный тестовый сертификат и команда подготовки; прежние TLS-файлы остались без изменений. E11 после проверки остановлен, данные сохранены.

```cmd
cd /d C:\vyz\incheneria\account-service
docker start account-service-e11-db-1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .local\redesign-2026-11-23\prepare-ui.ps1
scripts\ui-test.cmd --browser yandex ^
  --yandex "%LOCALAPPDATA%\Yandex\YandexBrowser\Application\browser.exe" ^
  --yandex-driver ".local\e11-continuation\browsers\yandex-driver\yandexdriver.exe" ^
  --ca ".local\redesign-2026-11-23\ui-tls\ca.pem" ^
  --spki ".local\redesign-2026-11-23\ui-tls\spki.txt" ^
  --output ".local\redesign-2026-11-23\yandex-repeat-03"
```

Каждый полный прогон создаёт новый синтетический набор в E11. Режим `--print-only` повторно проверяет только печать по предыдущим успешным данным. При блокировке временного профиля Windows путь сохраняется в `profileCleanupNotes`; результат проверок интерфейса и реального масштаба остаётся отдельным.

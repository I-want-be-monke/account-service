## Открытые ограничения

- Ручной проход создания пользователя, смены роли, блокировки и повторного входа в браузере ещё не завершён. Эти действия проверены интеграционными тестами, но не отмечены как ручные.
- Финансовые POST-маршруты появятся на E5–E6; тогда будет проверен запрет финансовых действий роли ADMIN на реальных операциях.
- Моя служебная консоль использует низкий уровень целостности Windows и членство `docker-users` с флагом `Deny only`. Docker Engine доступен в обычном CMD пользователя, что подтверждено Testcontainers; изменение ACL движка не требуется для работы проекта. Remote Desktop Commander доступен: Docker Engine 27.1.1 отвечал на команды, а Testcontainers создал настоящие контейнеры PostgreSQL 17.11.
- Локальный сертификат разработки самоподписан. Браузерный доступ к нему предоставил пользователь; системная проверка TLS не отключалась.

## Реализовано и проверено в E4

- Миграция V3 без изменения V1/V2: личные счета, последовательность уникальных неизменяемых номеров LS-XXXXXXXXXX, три статуса OPEN/SUSPENDED/CLOSED, история статусов, FK на клиента, ограничения дат/валюты/нулевого сальдо, блокировка изменения ключевых полей и повторного открытия CLOSED на уровне PostgreSQL.
- OPERATOR открывает счет активному клиенту, меняет статус после одноразового подтверждения с причиной и версией. Повтор того же UUID открытия возвращает прежний счет. Сотрудники видят и ищут счета, CLIENT видит только счета своей карточки. Клиенты ищутся по номеру счета; архивировать клиента с OPEN или SUSPENDED нельзя, в том числе при конкурентном открытии.
- История и обязательный аудит открытий/смены статуса фиксируются атомарно с изменением. При ошибке записи аудита транзакция откатывается. Сальдо нового счета всегда 0,00 RUB; закрытие допускается только при нуле.
- 5 ноября в пользовательском Windows CMD: mvnw.cmd clean verify — BUILD SUCCESS, 2/2 модульных, 20/20 интеграционных тестов (7 E4, 5 E3, 8 E1/E2) в PostgreSQL Testcontainers 17.11. Проверены повтор открытия, конкурирующее открытие/архивирование, права, CSRF, подтверждение, откат без обязательного аудита, реальные ограничения БД и повторная миграция. Отдельный mvnw.cmd test — BUILD SUCCESS, 2/2.
- На существующей базе с V1/V2 scripts\dev-up.cmd применил V3. До проверки было 5 пользователей и 2 клиента; на HTTPS выполнены реальные входы OPERATOR, CLIENT, ACCOUNTANT, GET /accounts и /my/accounts (200), запреты CLIENT общего списка и ACCOUNTANT открытия счета (403), отказ POST без CSRF (403), открытие и повтор без дубля, поиск по номеру, подготовка статуса без изменения БД, подтверждение SUSPENDED, две записи истории и две записи обязательного аудита. Тестовые счета оставлены для просмотра истории: 63b67c67-2851-4262-b6e6-67693f9ee669 и 286ba61e-f6f3-4b45-b565-573442efa6b7.
- После scripts\dev-down.cmd и scripts\dev-up.cmd существующий volume сохранил 5 пользователей, 2 клиента, 2 счета, 4 записи истории и 3 успешные миграции; readiness вернул HTTP 200. Приложение оставлено запущенным.

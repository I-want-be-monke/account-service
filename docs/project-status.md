## Открытые ограничения

- Ручной проход создания пользователя, смены роли, блокировки и повторного входа в браузере ещё не завершён. Эти действия проверены интеграционными тестами, но не отмечены как ручные.
- Финансовые POST-маршруты появятся на E5–E6; тогда будет проверен запрет финансовых действий роли ADMIN на реальных операциях.
- Моя служебная консоль использует низкий уровень целостности Windows и членство `docker-users` с флагом `Deny only`. Docker Engine доступен в обычном CMD пользователя, что подтверждено Testcontainers; изменение ACL движка не требуется для работы проекта. Remote Desktop Commander доступен: Docker Engine 27.1.1 отвечал на команды, а Testcontainers создал настоящие контейнеры PostgreSQL 17.11.
- Локальный сертификат разработки самоподписан. Браузерный доступ к нему предоставил пользователь; системная проверка TLS не отключалась.

## Реализовано и проверено в E3

- UR-05/07/19/20, SR-11/25, BR-02/05/10 (часть до таблицы счетов): карточки PERSON и ORGANIZATION; нормализация и уникальность идентификатора, контакты, версии, поиск и пагинация; архив и восстановление с причиной и одноразовым подтверждением; бизнес-аудит до/после внутри транзакции.
- Роль OPERATOR создаёт и редактирует карточки. ADMIN, ACCOUNTANT и MANAGER читают реестр. CLIENT читает только карточку, связанную с его учётной записью в PostgreSQL. Клиент не может получить общий список или чужую карточку.
- Миграции V1/V2 не редактировались и не добавлялись: ограничения и индексы client уже существовали. Docker volume сохранён.
- Запуск на Windows через Remote Desktop Commander: Docker Engine 27.1.1; mvnw.cmd clean verify — BUILD SUCCESS, 2 модульных и 13 интеграционных тестов (5 E3, 8 E1/E2) без ошибок; mvnw.cmd test — BUILD SUCCESS, 2/2.
- На работающем приложении: /login и readiness — 200; без входа /clients — 302; с настоящим входом OPERATOR /clients и /clients/new — 200, CLIENT /me/client — 200 и /clients — 403, ACCOUNTANT /clients — 200 и /clients/new — 403.
- На существующей базе оператор создал синтетическую карточку 052e0310-80aa-4ab4-9d6b-feca9479aff6, повтор ключа с другим регистром и пробелами получил 409, после отдельного подтверждения карточка стала ARCHIVED. В PostgreSQL проверены по одной записи аудита CLIENT_CREATED и CLIENT_STATUS_CHANGED. После dev-down.cmd и dev-up.cmd в БД остались две карточки (одна ранее существовавшая), пять пользователей, обе успешные миграции и архивная карточка. Примерная карточка оставлена для проверки истории и аудита.
- У скрипта dev-up.cmd ожидание заменено на ping, чтобы CMD под удалённым исполнителем не выдавал ошибку перенаправленного ввода от timeout.exe.

# Учебный импорт данных, формат 1

Пакет — каталог с `manifest.json`, `clients.csv`, `accounts.csv` и `operations.csv`. Все четыре файла используют UTF-8. BOM допустим. В CSV разделитель `;`, кавычка `"`, внутренняя кавычка в заключённом в кавычки поле записывается как `""`. Основание и причина исправления могут содержать переводы строк внутри такого поля. Пустая ячейка обозначает отсутствие необязательного значения. Поддерживается до 20 000 записей и 8 МиБ на CSV-файл, до 2 МиБ на манифест.

Заголовки обязательны и имеют указанный порядок.

```text
clients.csv
id;client_type;display_name;identifier_type;identifier_value;phone;email;status

accounts.csv
id;account_number;client_id;status;opened_on;closed_on;history_start_on;opening_balance;currency

operations.csv
id;account_id;kind;operation_date;amount;period_start;basis;payment_method;external_number;corrects_operation_id;target_amount;correction_reason;delta
```

| Запись | Проверки |
|---|---|
| Клиент | `id` — UUID. `client_type` — `PERSON` или `ORGANIZATION`. Имя, тип и значение идентификатора обязательны. Телефон и email необязательны. `status` — `ACTIVE` или `ARCHIVED`. Идентификатор нормализуется по правилам приложения. |
| Счёт | `id` и `client_id` — UUID. Клиент должен быть в том же пакете. Номер — `LS-` и десять цифр от `0000000001`. Валюта — `RUB`. `status` — `OPEN`, `SUSPENDED` или `CLOSED`. Для `CLOSED` нужны дата закрытия и нулевое итоговое сальдо. У архивного клиента допускаются только закрытые счета. |
| Даты | Формат `YYYY-MM-DD`. Начало доступной истории приходится на дату открытия или позже. Даты не могут быть в будущем. Операции располагаются по возрастанию даты внутри каждого счёта. Порядок записей одного дня сохраняется. Операция закрытого счёта относится к дате закрытия или более раннему дню доступной истории. |
| Суммы | Десятичная точка, до двух дробных знаков и до 17 целых знаков для денежного поля счёта или движения. `amount` положительна, `delta` и `opening_balance` могут быть отрицательными. |

Правила `operations.csv` зависят от `kind`.

| Вид | Поля и эффект |
|---|---|
| `CHARGE` | `period_start` — первое число расчётного месяца и не позже даты операции. Номер документа необязателен. `delta = amount`. |
| `PAYMENT` | Номер документа обязателен. `payment_method` — `MANUAL_TRANSFER` или `CASH_REGISTRATION`. `delta = -amount`. |
| `CORRECTION` | Указываются UUID предшествующего начисления или платежа того же счёта, неотрицательная `target_amount` и причина. Эффект рассчитывается от исходной суммы с учётом ранее проведённых исправлений, а `amount = abs(delta)`. Нулевой эффект недопустим. |

`basis` обязательно для всех видов. Поля, принадлежащие другим видам, оставляются пустыми. При наличии номера документа источник в БД — `IMPORT`. Уникальность проверяется по виду операции и нормализованному номеру в этом источнике. UUID, клиентские ключи и номера счетов сверяются как внутри пакета, так и с целевой БД.

Для полной истории с даты открытия входящее сальдо равно нулю. При переносе с начальным остатком `history_start_on` позже `opened_on`. Пакет содержит движения только с этой границы, а `opening_balance` покрывает историю до неё. Финальный баланс равен входящему остатку плюс сумма всех `delta`.

Манифест содержит ровно следующие поля.

| Поле | Значение |
|---|---|
| `version` | Целое число `1`. |
| `sourceName` | Метка источника до 255 символов, без пути. |
| `files` | Объект с ключами `clients.csv`, `accounts.csv`, `operations.csv`. Для каждого файла указываются `rows` и `sha256`. `rows` считает записи без заголовка, включая многострочную запись как одну. `sha256` — 64 строчные шестнадцатеричные цифры от исходных байтов файла. |
| `packageSha256` | SHA-256 канонического текста ниже. |
| `controlBalances` | Объект от номера счёта к строке с итоговым сальдо. Требуется значение для каждого и только каждого счёта пакета. |
| `controlDebt` | Строка с суммой положительных сальдо. |
| `controlAdvance` | Строка с суммой модулей отрицательных сальдо. |

Канонический текст кодируется UTF-8, разделитель строк — LF. После последней строки тоже ставится LF. Вместо `<sha>` подставляется хэш соответствующего файла. Байты самого JSON в идентификатор пакета не входят. Контрольные суммы и число записей из манифеста сверяются с содержимым при каждом запуске.

```text
account-service-import-v1
clients.csv:<sha>
accounts.csv:<sha>
operations.csv:<sha>
```

Синтетический пример находится в `migration/demo-package`. Команды импорта описаны в инструкции по развёртыванию. При прямом запуске JAR используются аргументы `--spring.profiles.active=migration`, `--import.mode=dry-run` или `--import.mode=apply`, `--import.directory=<каталог>`, `--import.actor=<логин>` и `--import.expected-database=<имя БД>`. Последний аргумент сверяется с `current_database()` и не переключает подключение. Настройки подключения передаются через окружение. Целевая база должна заранее пройти Flyway V6, исполнитель — существующий активный `ACCOUNTANT`.

`dry-run` выполняет только чтение БД. Новый корректный пакет получает `VALID`, уже применённый — `ALREADY_APPLIED`, а ошибочный — `INVALID` со списком причин. В отчёте `row` — номер логической записи CSV с учётом заголовка, где `1` — заголовок и `0` — ошибка уровня файла или подключения. Вывод ограничен первыми 100 замечаниями. Некорректный отчёт даёт код процесса `2`, успешный — `0`.

`apply` проверяет пакет повторно и записывает новых клиентов, счета и операции одной транзакцией. Операции проходят переход `PREPARED` → `POSTED` с действующими триггерами. Дата документа берётся из CSV, время проведения фиксирует импорт. Для счёта сохраняется техническая история применения состояния с пометкой `IMPORT`. После сверки PostgreSQL записывает `import_run`, связи происхождения и событие `IMPORT_APPLIED` с тем же UUID. Применение возвращает `APPLIED`. Повтор того же содержимого возвращает `ALREADY_APPLIED` и исходный UUID. Ошибка записи откатывает весь пакет. Если исполнитель уже был установлен, событие `IMPORT_REJECTED` записывается после отката отдельной транзакцией.

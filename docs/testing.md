# Проверка E9–E11

Полная проверка на Windows с Java 21 и Docker Desktop выполняется из CMD.

```bat
cd /d C:\vyz\incheneria\account-service
scripts\dev-down.cmd
mvnw.cmd clean verify
scripts\dev-up.cmd
```

Запускайте приложение после `BUILD SUCCESS`. Результаты JUnit находятся в `target\surefire-reports` и `target\failsafe-reports`. Для повторного прогона классов отчётов на остановленном приложении выполните `mvnw.cmd -Dit.test=ReportServiceIT,ReportExportIT verify`.

`src/test/resources/db/report-control.sql` содержит набор из §9.2. Интеграционные тесты загружают его в изолированную PostgreSQL Testcontainers с применёнными Flyway-миграциями. Проверяются суммы, дата исправления, баланс на прошлую дату, черновики, отрицательные и нулевые остатки, параметры, права, пагинация, CSV и согласованность при конкурентном проведении. Используйте скрипт в отдельной тестовой БД.

| Набор за октябрь 2026 | Ожидаемый результат, ₽ |
|---|---:|
| A на 31.10 | 550.00 |
| B на 31.10 | −300.00 |
| C на 31.10 | 0.00 |
| Долг по всем счетам | 550.00 |
| Авансы по всем счетам | 300.00 |
| Чистое сальдо | 250.00 |
| Исходные начисления / исправления / итог | 200.00 / −100.00 / 100.00 |
| Зарегистрированные платежи / исправления / итог | 900.00 / −50.00 / 850.00 |
| Входящее / изменение / исходящее | 1000.00 / −750.00 / 250.00 |

Для ручной проверки на тестовой базе войдите как ADMIN, сформируйте четыре отчёта и сравните суммы. Укажите размер страницы 1 в задолженности, пролистайте три счёта и проверьте общий итог 550.00 долга, 300.00 аванса и 250.00 чистого сальдо. Скачайте CSV, откройте печать и JSON. CSV содержит три детальные строки даже при показе одной строки в браузере.

Проверьте чтение под MANAGER и отказ в финансовом POST с действительным CSRF. Под OPERATOR и CLIENT прямые запросы HTML, печати, CSV и API должны возвращать 403. После штатного перезапуска повторите запрос отчёта.

## Восстановление и импорт E10

Целевой прогон из CMD при работающем Docker Desktop.

```bat
mvnw.cmd -Dit.test=BackupRestoreIT,MigrationImportIT verify
```

`BackupRestoreIT` копирует базу V5 штатными утилитами PostgreSQL 17, проверяет SHA‑256 при переносе в отдельный контейнер, восстанавливает схему, применяет V6 и проверяет вход, аудит, выписку и отчёт. Отдельная проверка ожидает ошибку `pg_dump` при неверной базе и отказ `pg_restore` для усечённого архива.

`MigrationImportIT` работает под ограниченной ролью PostgreSQL. Сценарии включают ошибочные поля и связи, повторные документы, dry-run без записей, откат пакета после проведений при сбое обязательного аудита, успешный перенос, конкурентный и последовательный повтор. Независимый SQL и запросы выписки и отчёта проверяют суммы. Учебный пакет содержит 2 клиентов, 3 счёта и 6 операций. Остатки `550.00`, `-300.00`, `0.00` дают долг `550.00` и аванс `300.00`.

Для эксплуатационной проверки выполните чистый `full`-запуск с отдельным именем проекта и портами. Снимите копию, выполните `restore-test.cmd` и после readiness войдите, откройте аудит, выписку и отчёт. Отметьте время от выбора копии до проверки документов. Проверьте явные отказы для отсутствующей и повреждённой копии, несовпадения SHA‑256, существующей цели и попытки выбрать имя рабочей БД. Команды приведены в [инструкции резервного копирования](backup.md) и [контракте импорта](import-format.md).

## Приёмка E11

```bat
mvnw.cmd -Dit.test=AcceptanceScenariosIT verify
```

Набор запускается на PostgreSQL Testcontainers. Для каждого разрешённого и запрещённого маршрута используется серверная проверка ролей и сеансов. Сценарий сбоя аудита доказывает откат уже подготовленных изменений PostgreSQL. Тесты повторного документа, одновременных проводок и гонки статуса проверяют эффект независимым SQL. [Результаты и сценарии](acceptance-functional.md)

Для нагрузки и отказов используйте `tests\performance\stand.cmd start`. Сверьте изоляцию и выполните генерацию, FIN‑09 до запуска, нагрузочный профиль и FIN‑09 после. Второй узел запускается командой `tests\performance\stand.cmd second`. Перед завершением сохраните JTL, отчёты, SQL-планы, логи и протокол восстановления. [Команды и формат результатов](../tests/performance/README.md) · [Матрица](acceptance.md)

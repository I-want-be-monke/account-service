# Сценарий защиты сервиса лицевых счетов

Демонстрация использует существующий проект в `C:\vyz\incheneria\account-service` и небольшой отдельный контур `account-service-defense`. Его PostgreSQL хранится в томе `account-service-defense_account-data`, база называется `account_service_defense`, HTTPS доступен на `18450`, HTTP на `18050`, PostgreSQL на `55439`. Все порты привязаны к `127.0.0.1`. При повторном запуске сохраняются подготовленные данные и пароли.

Заранее откройте обычный CMD и Docker Desktop. Проверьте JDK 21, существующие `.env` и `.local\dev.p12`. Скрипт подготовки читает пароль существующего учебного сертификата и создаёт отдельный `.local\defense.env` со случайными паролями БД и пяти учебных пользователей. Перед показом откройте этот файл локально, чтобы подготовить входы. Сохраните выбранные вами пароли новых пользователей отдельно от скриншотов и протокола. [Установка и сертификат](deployment.md)

В примерах `D` означает сегодняшнюю дату в виде `2026-11-23`, `M` — её месяц `2026-11`, `M01` — первое число месяца `2026-11-01`. При показе в другой день подставьте текущие даты. Выполните все четыре финансовых проведения в течение одного дня. Исправление получает текущую дату автоматически. Для повторного показа используйте новый суффикс имён и документов, например `defense2`, и создайте новый нулевой счёт через интерфейс.

Суммы для ввода и сверки CSV приведены с десятичной точкой. Интерфейс показывает те же значения с запятой, разделением тысяч и знаком рубля. Например, `1000.00` отображается как `1 000,00 ₽`.

## 20 шагов демонстрации

### 1. Запустить приложение из CMD

```bat
cd /d C:\vyz\incheneria\account-service
java -version
docker info --format "{{.NCPU}} {{.MemTotal}}"
scripts\demo-up.cmd
echo Exit code %ERRORLEVEL%
docker compose -f compose.yaml -p account-service-defense --env-file .local\defense.env --profile full ps
docker port account-service-defense-db-1 5432/tcp
docker inspect --format "{{range .Mounts}}{{.Name}} {{.Destination}}{{println}}{{end}}" account-service-defense-db-1
docker exec account-service-defense-db-1 psql -XAt --no-password -U account_owner -d account_service_defense -c "SELECT current_database()"
```

Ожидаются код 0, готовые контейнеры, порт `127.0.0.1:55439`, том `account-service-defense_account-data` и имя `account_service_defense`. `demo-up.cmd` вызывает существующий полный запуск с отдельными параметрами и собирает приложение из этого checkout. Откройте `https://localhost:18450/login`, проверьте сертификат `localhost` по уже используемому учебному сертификату. Подготовка отдельно доступна командой `powershell.exe -NoProfile -File scripts\prepare-demo.ps1`.

### 2. Войти администратором

Введите `demo-admin` и значение `DEMO_ADMIN_PASSWORD` из `.local\defense.env`. Покажите роль «Администратор» в верхней панели, боковое меню, активный раздел и переходы к пользователям, журналу и отчётам. Откройте любой раздел и вернитесь на главную. На узком окне раскройте меню кнопкой. Для разных ролей используйте отдельные профили браузера или явный выход кнопкой «Выйти» в верхней панели.

### 3. Создать пользователя и изменить его роль

В «Пользователи» выберите создание. Задайте логин `defense-reviewer`, имя `Руководитель демонстрации`, выбранный вами пароль длиной 12–128 символов и роль «Оператор». Клиента оставьте невыбранным. После создания найдите пользователя по логину и откройте редактирование. В разделе «Роль и доступ» выберите «Руководитель», статус «Активен», причину `Демонстрация изменения полномочий`. Нажмите «Перейти к подтверждению», проверьте старую и новую роль, затем «Подтвердить изменение». Новую роль покажите повторным входом `defense-reviewer` в отдельном профиле браузера. Позже этот пользователь сформирует отчёты.

### 4. Создать карточку клиента

Войдите `demo-operator` с паролем `DEMO_OPERATOR_PASSWORD`, покажите доступные действия его главной страницы и откройте «Клиенты» → создание. Выберите «Физическое лицо», имя `Клиент защиты defense1`, тип идентификатора `DEMO`, значение `DEFENSE-1`, email `defense1@example.invalid`. Сохраните карточку и найдите её по имени в реестре. Карточка клиента и пользователь для входа создаются отдельными действиями.

### 5. Открыть нулевой лицевой счёт

Из созданной карточки нажмите «Открыть счёт», оставьте сегодняшнюю дату и подтвердите. Покажите автоматически присвоенный номер, валюту и сальдо `0,00 ₽`. Сохраните номер как `ACCOUNT_NUMBER`. Для технической проверки запрета доступа в шаге 15 сохраните UUID из адреса `/accounts/<UUID>` как `ACCOUNT_ID`.

Для проверки ограничения владения также откройте нулевой счёт существующему «Учебному клиенту» из профиля `dev` и сохраните его UUID как `OTHER_ACCOUNT_ID`. У этого счёта другой владелец. Все дальнейшие финансовые действия выполняйте на `ACCOUNT_ID`.

### 6. Создать вход для нового клиента

В профиле `demo-admin` откройте создание пользователя. Задайте логин `defense-client`, имя `Клиент защиты`, собственный пароль длиной 12–128 символов и роль «Клиент». В поиске клиента введите `Клиент защиты defense1` и выберите созданную карточку. После создания откройте редактирование и покажите выбранное имя клиента.

### 7. Провести начисление 1000 ₽

Войдите `demo-accountant` с `DEMO_ACCOUNTANT_PASSWORD`. Откройте «Финансовые операции», найдите `ACCOUNT_NUMBER`, перейдите к счёту и начислению. Введите дату `D`, сумму `1000.00`, расчётный месяц `M01`, основание `Начисление для защиты defense1`, номер расчётного документа `DEFENSE-1-CHARGE`.

Нажмите «Сохранить черновик» и покажите, что сальдо осталось нулевым. Вернитесь на главную бухгалтера, найдите собственный черновик в ограниченном списке последних пяти и откройте его. Сохраните ссылку на исходное начисление. Нажмите «Проверить и провести», сверьте сумму и счёт, затем «Подтвердить проведение». Сальдо станет `1 000,00 ₽`.

### 8. Провести платёж 400 ₽

На том же счёте выберите «Зарегистрировать платеж». Введите дату `D`, сумму `400.00`, основание `Платёж для защиты defense1`, способ «Ручной перевод», номер `DEFENSE-1-PAYMENT`. Сохраните черновик, покажите сальдо `1000.00`, затем подтвердите проведение на отдельной странице. Сальдо станет `600.00`. Сохраните ссылку на исходный платёж.

### 9. Исправить начисление до 900 ₽

Откройте исходное начисление 1000 ₽ и нажмите «Создать исправление». Задайте целевую сумму `900.00`, причину `Исправление суммы начисления после проверки`, основание `Уточнённый расчёт defense1`. Нажмите «Подготовить исправление», затем «Проверить и провести» и «Подтвердить проведение». Отдельная корректировка имеет изменение `-100.00`, сальдо становится `500.00`. Покажите ссылку корректировки на исходное начисление.

### 10. Исправить платёж до 350 ₽ и проверить сальдо

Откройте исходный платёж 400 ₽, создайте исправление с целевой суммой `350.00`, причиной `Уточнение зарегистрированного платежа` и основанием `Исправленный платёжный документ defense1`. Подтвердите проведение. Изменение сальдо составляет `+50.00`, итог — `550.00`.

| Проведение | Изменение сальдо, ₽ | Сальдо после, ₽ |
|---|---:|---:|
| Начисление | +1000.00 | 1000.00 |
| Платёж | −400.00 | 600.00 |
| Исправление начисления | −100.00 | 500.00 |
| Исправление платежа | +50.00 | 550.00 |

### 11. Показать историю

Под бухгалтером выберите «Операции по счету». Покажите исходные начисление и платёж и две отдельные корректировки, даты, документы, статусы и ссылки. Откройте исходную операцию и её список проведённых исправлений. Итоговая учётная сумма начисления равна `900.00`, платежа `350.00`, разность равна `550.00`.

### 12. Войти в личный кабинет клиента

В отдельном профиле войдите `defense-client`. Покажите его главную страницу со своими счетами и остатками. Откройте «Моя карточка», затем «Мои счета». Найдите `ACCOUNT_NUMBER`, сальдо `550,00 ₽`, откройте карточку и историю. Список ограничен клиентом, указанным при создании этого пользователя.

### 13. Сформировать выписку и выгрузить CSV

Под тем же клиентом нажмите «Сформировать выписку», в обеих датах укажите `D` и сформируйте документ. Ожидаются входящее сальдо `0.00`, увеличение `1050.00`, уменьшение `500.00`, исходящее сальдо `550.00` и четыре строки движений. Проверьте остаток после каждой строки по таблице шага 10.

Покажите печатное представление и сохраните CSV кнопкой экспорта. Откройте файл как UTF-8 с разделителем `;` и сверьте суммы и четыре операции. Сохраните UUID счёта и дату периода вместе с файлом. [Правила выписки](user-guide.md)

### 14. Сформировать четыре финансовых отчёта

Войдите созданным `defense-reviewer` с ролью «Руководитель». Покажите его главную страницу и откройте «Финансовые отчёты» в боковом меню. Введите `Клиент защиты defense1`, выберите результат поиска и поочерёдно сформируйте четыре вида через вкладки. Оставьте статус «Все статусы» и размер страницы 20. Для начислений и платежей выберите месяц `M`, для задолженности дату `D`, для движения даты от `D` до `D`. Ожидаемые результаты относятся к одному созданному счёту.

| Отчёт | Контрольные значения, ₽ |
|---|---|
| Начисления | Исходные 1000.00, исправления −100.00, итог 900.00 |
| Платежи | Исходные 400.00, исправления −50.00, итог 350.00 |
| Задолженность | Долг 550.00, аванс 0.00, сальдо 550.00 |
| Движение | Входящее 0.00, начисления 1000.00, платежи 400.00, корректировки −50.00, увеличение 1050.00, уменьшение 500.00, изменение 550.00, исходящее 550.00 |

Покажите имя клиента в параметрах результата, итоговые карточки и переход по номеру счёта. Вернитесь к фильтрам, сбросьте клиента и сформируйте отчёт по всем клиентам. Сравните итоги при размере страницы 1 и 20. Затем снова выберите созданного клиента и скачайте полный CSV. В печатном виде покажите пояснение о текущей странице деталей и общих итогах. В предпросмотре печати проверьте отсутствие меню и кнопок.

Для проверки клавиатуры переведите фокус Tab в поиск клиента, выберите совпадение стрелками и Enter, затем проверьте Escape. В узком окне прокрутите широкую таблицу в её области с клавиатуры. При отключённом JavaScript используйте «Найти» и «Выбрать», затем сформируйте тот же отчёт. Сохраните снимки широкой и узкой версии и PDF выписки и отчёта. При переносе показа на другой месяц все четыре проведения должны попасть в выбранный период.

### 15. Показать ограничения доступа

Под `defense-client` вручную откройте `https://localhost:18450/admin/users`, затем `/reports` — сервер должен ответить 403. Под `demo-admin` та же форма начисления также должна вернуть 403. Вернитесь в разрешённые страницы и покажите сальдо `550.00`.

Откройте подробности смены роли и корректировки. Покажите инициатора, время, причину, результат и идентификатор запроса. Технические фильтры объекта можно уточнить по уже видимой строке журнала.

### 17. Создать проверенную резервную копию демонстрационной БД

В том же CMD явно выберите контур и отдельный каталог копий.

```bat
set "ACCOUNT_OPS_COMPOSE_PROJECT=account-service-defense"
set "ACCOUNT_OPS_ENV_FILE=C:\vyz\incheneria\account-service\.local\defense.env"
set "ACCOUNT_BACKUP_ROOT=C:\vyz\incheneria\account-service\.local\defense-backups"
scripts\backup.cmd
echo Exit code %ERRORLEVEL%
dir /b /ad /o-n ".local\defense-backups\backup-*"
```

Ожидаются код 0 и `BACKUP OK`. Выберите только что созданный каталог. Следующие команды выбирают первый по убыванию имени `backup-*` из отдельного каталога показа, затем печатают его манифест.

```bat
set "DEMO_BACKUP="
for /f "delims=" %B in ('dir /b /ad /o-n ".local\defense-backups\backup-*"') do @if not defined DEMO_BACKUP set "DEMO_BACKUP=C:\vyz\incheneria\account-service\.local\defense-backups\%B"
type "%DEMO_BACKUP%\backup.json"
type "%DEMO_BACKUP%\SHA256SUMS"
```

Проверьте `sourceDatabase=account_service_defense`, время снимка, размер и SHA-256. При размещении команд в отдельном `.cmd` замените `%B` на `%%B`. [Проверки архива](backup.md)

### 18. Восстановить копию в проверочную БД

Сначала штатно остановите только демонстрационный контур, чтобы освободить память, затем восстановите явно выбранный архив.

```bat
scripts\full-down.cmd account-service-defense .local\defense.env
scripts\restore-test.cmd "%DEMO_BACKUP%" -HttpsPort 18443
echo Exit code %ERRORLEVEL%
```

Ожидаются код 0, проверка SHA-256, SQL-сверка и сообщение `RESTORE READY`. Откройте `https://localhost:18443/login`, заново войдите `defense-client` с тем же паролем из шага 6. Проверьте счёт `ACCOUNT_NUMBER`, сальдо `550.00`, четыре движения и выписку за `D`. Под `defense-reviewer` сверьте четыре отчёта, под `demo-admin` — пользователей и аудит. Результаты SQL и журналы находятся в последнем `.local\restore-test\run-*`. После проверки выполните `scripts\restore-test-down.cmd`.

Повторное открытие основного демонстрационного контура выполняется командой `scripts\demo-up.cmd`. Данные в его именованном томе сохраняются. [Устройство проверочного восстановления](backup.md)

### 19. Показать автоматизированные проверки

Откройте актуальные [результаты приёмки](acceptance.md) и [описание тестов](testing.md). Исторический E11 от 06.11.2026 содержит 99 Maven-тестов и 315 проверок доступа по пяти ролям. Для нового интерфейса покажите отдельный фактический итог, дату, версии браузеров и снимки «до/после» из [отчёта о переработке](ui-redesign.md). До заполнения новых протоколов используйте пометку «ОЖИДАЕТ ПРОГОНА».

Команда воспроизведения полной регрессии приведена ниже. Выполняйте её после остановки экземпляров Java, использующих `target\account-service.jar`, включая проверочный экземпляр восстановления. После сборки запускайте нужный сервис штатной командой.

```bat
cd /d C:\vyz\incheneria\account-service
if exist .local\restore-test\state.json scripts\restore-test-down.cmd
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\stop-app.ps1
mvnw.cmd clean verify
echo Exit code %ERRORLEVEL%
```

После `BUILD SUCCESS` верните рабочее приложение командой `scripts\dev-up.cmd` и проверьте `https://localhost:8443/actuator/health/readiness`. Демонстрационный контур можно снова запустить через `scripts\demo-up.cmd`.

### 20. Показать фактическую нагрузку и оставшиеся критерии

Покажите сокращённый E11 в [матрице приёмки](acceptance.md) и [ограничениях](limitations.md). Выполнены три прогона по 60 HTTPS-сеансов на 50 000 счетов и 250 000 исходных проведённых операций. Получены 9 461 HTTP-запрос, 0 неожиданных ошибок и 5xx, p95 экранных GET 68 мс, p95 смешанной выборки GET и POST 70 мс. Для 360 отчётов максимум составил 5,040 с. Проверены 214 финансовых действий нагрузки, FIN-09 дал 0 расхождений.

Укажите, что PERF-01, PERF-02 и AT-09 сохраняют `NOT VERIFIED`. Полный профиль требует 300 сеансов на 200 000 счетов, минимум 1 млн проведений и три прогона с фазами 5/5/20 минут. При проверке 23.11.2026 Docker показывал 7 976 271 872 байта памяти при минимуме 8 000 000 000 байт. Подготовка защиты и демонстрация функций выполнены в пределах доступного компьютера. Для будущей пилотной проверки сохранена [инструкция стенда](pilot-stand.md).

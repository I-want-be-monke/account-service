# Переработка интерфейса сервиса лицевых счетов

Рабочий отчёт от 23.11.2026. Документ описывает реализацию и охват изменений. Поля результатов заполняются после фактических проверок текущей сборки. Исторические результаты E11 от 06.11.2026 сохранены в прежних протоколах. PERF-01, PERF-02 и AT-09 имеют статус **NOT VERIFIED**.

## Дизайн-система и устройство

Выбран Tabler 1.7.5, набор компонентов на основе Bootstrap. Он предоставляет карточки, формы, таблицы, кнопки, вкладки, уведомления и навигационные элементы для рабочих приложений. Компоненты подключены локально из `src/main/resources/static/vendor/tabler/1.7.5`. Это даёт воспроизводимую версию оформления при локальном запуске. Проект Tabler распространяется по MIT. [Документация Tabler](https://docs.tabler.io/ui) · [Исходный проект и лицензия](https://github.com/tabler/tabler)

В комплект поставки входят `tabler.min.css`, `tabler.min.js`, файл лицензии и манифест версии с хешами. Перед размещением проверяется SHA-512 npm-пакета. Сведения о поставке сохранены рядом с ресурсами. [Локальная лицензия MIT](../src/main/resources/static/vendor/tabler/1.7.5/LICENSE) · [Манифест версии](../src/main/resources/static/vendor/tabler/1.7.5/manifest.json)

Пример Bootstrap Dashboard использован как ориентир размещения боковой навигации и основной области. Рекомендации Carbon для таблиц использованы при выделении панели фильтров, заголовка, строк и пагинации. В приложение подключена библиотека Tabler. [Bootstrap Dashboard](https://getbootstrap.com/docs/5.3/examples/dashboard/) · [Carbon Data Table](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines)

Общие фрагменты Thymeleaf находятся в `templates/fragments/layout.html`, `templates/fragments/client-picker.html` и `templates/fragments/ui.html`. Layout задаёт подключение ресурсов, боковое меню и верхнюю панель. Шаблон страницы передаёт основное содержимое с одним заголовком первого уровня. `ui.html` предоставляет общие статусы, уведомления, ссылки-кнопки, пагинацию и простые поля с подписями. Они повторно используются в отчётах, выписках, списках клиентов и счетов, форме открытия счёта и главной странице. Поля со специальными ограничениями сохраняют явные атрибуты своего шаблона. Общие стили находятся в `static/css/app.css`, поведение меню и поиска в `static/js/app.js`, правила печати в `static/css/print.css`.

`UiFormat` форматирует суммы, даты и подписи статусов для HTML. Исходные финансовые значения сохраняются в атрибутах `data-value` для сверки. Форматы CSV и JSON продолжают использовать исходные поля и точные денежные строки. Полномочия проверяются существующими серверными сервисами и политиками доступа.

## Навигация и главные страницы

Боковое меню содержит восемь разделов. Набор видимых пунктов зависит от роли. Активный пункт обозначен через `aria-current`, свёрнутое меню сохраняет понятные подписи. Верхняя панель содержит путь к странице, имя пользователя, роль и выход. На узком экране меню открывается кнопкой.

| Раздел | Маршрут и назначение |
|---|---|
| Главная | `/`, действия и доступные данные роли |
| Пользователи | `/admin/users`, администратор |
| Клиенты | `/clients`, для клиента собственная карточка `/me/client` |
| Лицевые счета | `/accounts`, для клиента `/my/accounts` |
| Финансовые операции | `/workspace/operations`, выбор счёта для истории и доступных действий |
| Выписки | `/workspace/statements`, выбор счёта для документа |
| Финансовые отчёты | `/reports`, администратор, бухгалтер и руководитель |
| Журнал действий | `/audit`, администратор и руководитель с разрешённым составом событий |

Новые маршруты `/workspace/operations` и `/workspace/statements` выполняют выборку счетов для перехода к существующим страницам. Клиент получает свои счета. Сотрудник получает разрешённый реестр с поиском по номеру. Полномочия финансовых команд определяются прежними маршрутами и сервисами.

| Роль | Содержимое главной страницы |
|---|---|
| Администратор | Переходы к пользователям, доступу, журналу, клиентам, счетам и отчётам |
| Оператор | Действия для создания клиента, поиска карточки и открытия счёта |
| Бухгалтер | Переходы к операциям, выпискам и отчётам, до пяти последних собственных черновиков |
| Руководитель | Переходы к отчётам, просмотру клиентов и счетов, разрешённому журналу |
| Клиент | Первые 20 собственных счетов с остатками, общее число счетов и переход ко всему списку, истории и выпискам |

Данные клиента поступают через `AccountService.own`. Главная показывает первую страницу и общее количество собственных счетов. Суммы относятся к конкретным показанным счетам. Черновики бухгалтера ограничены автором и состоянием `PREPARED`, упорядочены по времени создания с устойчивым дополнительным ключом. Для каждого черновика показаны счёт, дата, сумма и переход к проверке. Остальные карточки главной страницы являются действиями и пояснениями. Каждой роли предложено по три основных действия.

## Выбор клиента и отчёты

В отчётах четыре одинаково оформленные вкладки. Форма показывает месяц для начислений и платежей, дату для задолженности либо две даты для движения. Дополнительные фильтры содержат клиента, текущий статус счёта и размер страницы.

Выбор клиента использует поле с подсказками. `/ui/clients/search?q=` вызывает существующий `ClientService.search` и возвращает не более 20 вариантов с полями `id`, `name`, `identifier`. Endpoint доступен администратору, оператору, бухгалтеру и руководителю. Оператор использует его в разрешённых формах реестра, при этом отчёты доступны трём прежним ролям. Клиенту общий поиск закрыт.

В форме имя показывается пользователю, а выбранный идентификатор передаётся скрытым полем `clientId`. Изменение текста сбрасывает выбор. Сервер отчёта проверяет согласованность имени и выбранного клиента, чтобы введённое новое имя не использовало предыдущий скрытый ID. Подсказки доступны стрелками и Enter, Escape закрывает список. Текст результатов выводится с экранированием.

Без JavaScript кнопка «Найти» отправляет GET на `/reports` с `clientQuery`. Сервер возвращает ограниченный список с кнопками «Выбрать». Выбор сохраняет вид отчёта, период, статус и размер страницы. Параметры представления удаляются перед строгим разбором финансового запроса. Форма с паролем использует отдельный GET-поиск вне отправки пароля.

Результат отчёта показывает имя клиента, период, дату формирования, итоговые карточки и таблицу. Итоги относятся ко всему фильтру. Пагинация меняет детали. CSV включает все строки выбранного фильтра, печать содержит текущую страницу и общие итоги с явным пояснением. JSON доступен в раскрываемом блоке для интеграции.

## Что исправлено при проверке

Исправлены переполнение страницы входа на ширине 768 px, позднее создание CSRF-токена в длинном layout, вывод события без типа объекта, перенос таблицы выписки целиком на следующий лист, активный раздел выписок и ошибки полей финансовых форм. Автоматизация явно прокручивает элемент перед обычным кликом; блокировка временного профиля Windows записывается отдельно от результатов сценария. Серверные ограничения и арифметика операций сохранены.

Рекомендации по таблицам и поиску сверены с [Carbon Data table](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines) и [Carbon Search](https://www.carbondesignsystem.com/building-blocks/core/components/search/guidelines). Проверка масштаба ориентируется на [WCAG 2.2 Resize Text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html); это проверка выбранных критериев доступности.

Финансовая сверка изолированной тестовой базы после прогона: все восемь проверок целостности дали ноль нарушений; 250 384 проведённым документам соответствуют 250 384 успешных события аудита. Это проверка сохранности на сокращённом наборе, без изменения статусов пилотной нагрузки. [Сверка](evidence/ui-redesign-2026-11-23/e11-financial-reconciliation.json). Тестовый контур E11 остановлен, его том сохранён.
